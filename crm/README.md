# Eva CRM — работа с клиентами

> **Черновик, версия 1.** Рабочая версия сейчас — [Eva CRM 2.0](v2/README.md): кастдев и подключение экспертов, партнёров и амбассадоров в три шага, база вопросов, анкеты по единой ссылке. Эта версия остаётся как запас идей и подробное ТЗ.

CRM Eva Space в едином стиле со штабом Eva Club. Одна клиентка — одна карточка со всей историей: анкета из приложения, касания (сообщения, рассылки, пуши, звонки с записями), оплаты и пополнения, задачи, рефералы. Воронки продаж, экспертов и партнёров, сегменты с условиями, теги, групповые чаты, ежемесячные реферальные выплаты и отчёты — из одной базы.

- **Техническое задание v2** — [TZ.md](TZ.md): база данных, критерии этапов, автоматика, рефералы, интеграции, закон, план внедрения, решения для команды.
- **Открыть:** артефакт Claude [«Eva CRM — работа с клиентами»](https://claude.ai/artifact/HjC5qXEcVj5R42yw2Q4cYZ) (общая база для всей команды, доступ выдаёт владелец через «Поделиться») или `crm/index.html` на любом статическом сервере. Во втором случае данные живут только в этом браузере, а при первом открытии загружается пример.

## Разделы

| Раздел | Что там |
| --- | --- |
| **Дашборд** | новые контакты, первые оплаты, выручка, подписки, план квартала, «ждут ответа»; воронка; «Требует внимания» (без ответа, свободные заявки, просроченные задачи, неоплаченные счета, без касания, заканчивается подписка); задачи; деньги по месяцам; источники; менеджеры |
| **Клиенты** | таблица базы: колонки на выбор из схемы, быстрые виды, фильтры, конструктор условий и сохранённые виды; массово — менеджер, тег, этап, задача, рассылка, выгрузка; загрузка CSV с защитой от дублей |
| **Карточка** | этапы стрелками, композер (сообщение, звонок, заметка, задача, оплата или счёт, встреча), лента и вкладки (переписка, звонки с записями, оплаты, задачи, рассылки, рефералы), профиль: контакты, анкета, подписка и деньги, согласия, активность, откуда пришла, чаты, предложения партнёров |
| **Воронки** | доска с перетаскиванием для продаж, экспертов, партнёров и своих воронок; фильтр по сегментам; матрица «сегменты × этапы»; критерии этапов |
| **Сообщения** | все диалоги по каналам, «ждут ответа», групповые чаты (UNICONF — чат конференции), заявки из приложения |
| **Касания** | рассылки с проверкой согласий и лимитов, цепочки прогрева, шаблоны, частота касаний |
| **Эксперты** | цель 50 экспертов и 150 мастер-классов, съёмки, таблица, карточка: заявка, условия, контент, продажи и доля |
| **Партнёры** | карточки с условиями, спецпредложениями, адресом и контактным лицом; все предложения с промокодами; вознаграждения |
| **Рефералы** | пригласившие, воронка, реестр выплат месяца (на карту или на баланс +10%), условия программы |
| **Отчёты** | воронка в разрезах, деньги, удержание по когортам, менеджеры, каналы, конструктор «поле × показатели» |
| **Настройки** | команда и роли («как видит» сотрудник), воронки и этапы, сегменты и условия, теги, интеграции, схема базы, данные |

## Как пользоваться — для команды

**Каждый день менеджеру:**
1. Утром откройте **Дашборд → Требует внимания**. Сначала ответьте тем, кто ждёт ответа, потом возьмите свободные заявки. Норма ответа — 15 минут.
2. Работайте из карточки. Написали, позвонили, выставили счёт — всё записывается в ленту. После разговора ставьте задачу со сроком: без следующего шага клиентка «повисает».
3. Счёт → «Счёт выставлен», оплата → «Оплата получена»: эти этапы меняются сами. Остальные этапы переносите на доске или стрелками в карточке. В отказ — с причиной.

**Раз в неделю старшему:** «Отчёты → Менеджеры» и «Воронка в разрезе сегмента», чистка «Без касания 7+ дней».

**Раз в месяц куратору, до 10 числа:** «Рефералы → Реестр выплат» за прошлый месяц. Зачислить на балансы, выплатить на карту, выгрузить реестр для бухгалтерии.

**Руководителю:** «Настройки → Команда» — выдать роли. Откройте доступ к артефакту сотруднику: при первом входе он появится с ролью «Менеджер».

Все модули собираются в одну область видимости, порядок — по имени файла. Правите `src/`, запускаете `python3 build.py --check`, коммитите и `src/`, и собранный файл.

**Схема таблицы — в одном месте.** Таблица, фильтры, условия сегментов, импорт CSV и страница «Схема базы» строятся из `CLIENT_FIELDS` в `01-config.js`. Новое поле добавляется одной строкой.

### Данные

В артефакте используется общая база `claude.use('db')`, **одна запись — один документ**. Коллекции:
- `team`, `clients`, `experts`, `partners` — команда, клиентки, эксперты, партнёры;
- `chats` — групповые чаты, `campaigns` — рассылки;
- `payouts` — реестры выплат, документ на месяц `YYYY-MM`;
- `cfg` — настройки: `funnels`, `segments`, `tags`, `templates`, `sequences`, `views`, `integrations`, `settings`, `meta`.

История клиентки лежит внутри её документа картой `ev: {id: событие}`. `db.update()` сливает вложенные объекты, поэтому два менеджера, одновременно записавшие звонок и сообщение одной клиентке, не затирают друг друга. LTV, подписка, сегмент, последнее касание и реферальные начисления не хранятся, а считаются из истории.

Лимит артефакта — 5 000 документов, примерно 4 500 клиенток. Для рабочей базы — PostgreSQL на сервере в России, схема в [TZ.md](TZ.md) §3.5.

### Про безопасность — честно

Роли разделяют интерфейс внутри команды. Граница доступа — сам артефакт: у кого есть к нему доступ, тот технически может прочитать общую базу. Артефакт с общей базой открывается только внутри организации. **Реальные персональные данные клиенток сюда не загружаем** (152-ФЗ требует хранения в России). Прототип — для отработки процессов на демо-данных. В браузере данные общей базы не кешируются.
